## 🎯 Introduction

SOLID is an acronym for five design principles intended to make software designs more understandable, flexible, and maintainable. This repository provides clear examples of each principle with both "good" and "bad" implementations to illustrate proper adherence versus common violations.

## 📚 Principles

### 1. Single Responsibility Principle (SRP)
**"A class should have only one reason to change."**

- Each class should have a single responsibility
- Focuses on cohesion and separation of concerns
- Reduces coupling between different functionalities

### 2. Open/Closed Principle (OCP)
**"Software entities should be open for extension but closed for modification."**

- Extend functionality without modifying existing code
- Achieved through abstraction and polymorphism
- Promotes code reusability and stability

### 3. Liskov Substitution Principle (LSP)
**"Objects of a superclass should be replaceable with objects of its subclasses without breaking the application."**

- Subtypes must be behaviorally substitutable for their base types
- Ensures inheritance is used correctly
- Prevents unexpected behavior in polymorphic code

### 4. Interface Segregation Principle (ISP)
**"Clients should not be forced to depend on interfaces they do not use."**

- Prevents "fat" interfaces
- Promotes specific, client-focused interfaces
- Reduces the impact of changes

### 5. Dependency Inversion Principle (DIP)
**"Depend on abstractions, not on concretions."**

- High-level modules shouldn't depend on low-level modules
- Both should depend on abstractions
- Enables better testability and flexibility
